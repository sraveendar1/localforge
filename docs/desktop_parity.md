# Desktop Parity Plan

The localforge desktop app is native-first, with buttons, menus, and panels being the primary way to interact with the app. An embedded CLI view exists but is intended for advanced users or exceptional cases; normal users should never need it.

## Recent Changes

- **2026-09-30 (backend start-up visibility; v0.1.3 signing regression)**: Reported: after opening a folder in the packaged app "the trusted folder didn't happen". Cause found: v0.1.3's `bundle.macOS.signingIdentity: "-"` made Tauri ad-hoc sign the whole bundle **including the PyInstaller backend, with the hardened runtime on** (Tauri's `hardenedRuntime` defaults to true), and a PyInstaller onefile binary then aborts at launch ("mapping process and mapped file have different Team IDs"). No backend meant no `ready`, no trust prompt, no setup -- and the app gave no sign of it: it never listened to the backend's stderr, and an exit just set `connected: false`. Fixes: `hardenedRuntime: false` plus an `Entitlements.plist` (`disable-library-validation`, `allow-unsigned-executable-memory`, `allow-dyld-environment-variables`) for any future hardened/notarized build (keys checked against the installed Tauri schema); a macOS CI step that runs the bundled backend from inside the signed `.app` and fails the job if it can't start; and `BackendStatus.tsx`, which shows "Starting localforge…" while waiting for `ready` (a slow-start note at 12s, a stuck warning with Try again at 40s), "localforge didn't start" with the backend's own stderr plus Try again / Copy details if it exits first, a calm "you chose not to trust this folder" after a declined trust, and a banner with Restart if it dies mid-conversation. `session_reset` (/clear) now keeps `connected`, or it would have looked like a dropped connection. The Rust exit event still carries no exit code (an unverified edit to code that can't be compiled here), so the stderr tail is what identifies a failure.
- **2026-10-02 (paid delegates labelled as paid)**: A coding/docs/general task pinned to a paid model (e.g. Claude Haiku through an API key) was drawn as "Local model claude-haiku-…" and counted under Local models and local tokens, because the delegate card hard-coded "Local model" and `delegate_started`/`delegate_finished` carried no runtime. They now carry `runtime` (`ollama`/`api`/`cli`) and `provider`: the card says **Paid model** (amber, with Provider API key/login) for a cloud delegate and **Local model** otherwise, a paid delegate isn't added to the local-model list or local token total (its tokens and cost come with the run's stats under Paid models), and the terminal's activity line says "paid model, via Anthropic API key" instead of "open-weighted model" (`cli._delegate_kind`).
- **2026-10-02 (paste or drop an image)**: Cmd/Ctrl+V with an image on the clipboard (a screenshot) or dropping an image file onto the message box now attaches it, same as the 📎 button (`attachImageFile` in `App.tsx`; one image per message, sent as base64). Before, only the button worked: the box had no paste or drop handler. A text paste is untouched. Tauri's own file-drop handling swallowed drops before the page saw them, so the window config sets `dragDropEnabled: false` (the app doesn't use native file drops; the key is checked against the CLI's config schema, not run on a Mac). The terminal version can't take pasted images: a terminal only passes text.
- **2026-10-02 (goal from the first request, progress log, visible queue)**: The first real request typed in a project (a greeting or a few words doesn't count) is recorded as its goal in `.localforge/goal.md` at once and shown in Overall goal; until AGENTS.md has its own "What this project is" section that's what the panel shows. Overall goal shows the last few progress lines. Plain text (`brief.py`: `record_goal`, `with_goal`, `with_progress`, `progress_line`), no model needed. The Plan is the current task's steps only; requests sent while a task runs are now listed in a **Queue** section on the right and as **Up next** under the Plan (they were only in a strip above the message box), with Clear queue. The "run /goals" hint is gone from the panel (the desktop has no `/goals`).
- **2026-10-01 (right panel; changing models after setup)**: Active LLMs is now a set of small cards (model name on its own line, then what it's for / how it's reached, a pulsing dot while one is working) instead of a row of columns that wrapped unevenly; paid models show their roles as chips. ## CLI Subcommands -> Desktop

Every row marked ✅ is reachable two ways in the app: through a dedicated
panel/control where one exists, and always through the chat input as the
literal slash command (`/model claude-opus-5`, `/doctor`, ...) — the input
autocompletes every one of these (`SlashMenu.tsx`) and the reply renders as
its own message in the conversation.

## Protocol Gaps

- **Setup wizard, `/delete`, `/uninstall`, `/theme`**: none of these have a
  server message type in `serve.py` yet (`handle()` has no case for
  `/setup`, `/delete`, `/uninstall`, or `/theme` — typing them just gets
  "Unknown command"). These need both new protocol messages and dedicated
  UI (a setup flow, a delete/uninstall confirmation dialog), which is a
  materially bigger feature than the rest of this table; run them from a
  terminal in the meantime.
- Everything else in the table above is done — this doc previously listed
  `/compact`, `/summary`, `/tell`, `/why`, `/help`, `/models`, `/installed`,
  `/catalog`, `/doctor`, `/model`, and y/n/a approvals as not done or not
  implemented, but the frontend/backend code already supported all of them
  by the time this was last accurate; see **Recent Changes** above for what
  was actually still broken (mostly missing event handlers, not missing
  features) and has now been fixed.
